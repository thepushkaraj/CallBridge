The wire

The whole protocol
is this.

Any client that can POST JSON can stand in for the phone. curl is a valid test device. One request, one notification. No session, no second format, no ack beyond the status code.

anywhere
$ curl -i http://192.168.1.42:8765/call \
    -H 'Content-Type: application/json' \
    -d '{"event":"ringing","number":"+15550148291",
         "caller":"Alex","device":"Pixel 8"}'

Opt-in

Texts stay off
until you ask.

SMS forwarding is a switch, and it starts off. Leave it off and CallBridge never reads a message. Turn it on and any text containing a code gets a Copy code button on your Mac. One tap copies it. Nothing is logged.

Honesty

The limits, on purpose.

Delivery
One try. Four seconds. No queue, no retry. If the Mac is asleep, that ring is gone. That is what “no server” means.
Network
LAN-only. The phone refuses anything outside the private ranges. It will not send a notification through the internet, ever.
Transport
Plain HTTP, like the traffic between your printer and your Mac. Fine on a network you trust; the wrong tool for a café.
Codebase
~3,000 lines you can read in an evening. The protocol fits on one page. There is nowhere to hide anything.
